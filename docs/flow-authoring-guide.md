# 图色脚本流程制作指南（安卓手游通用）

> 面向用本工作台（模板采集 + 流程编排）制作挂机流程的实操思路。
> 不绑定具体游戏版本：界面截图换成你自己的，骨架照抄。

## 零、总原则

图色脚本不是"录屏回放"，是**给瞎子导航**。每一步只做三件事：

1. **认路**——现在在哪个界面（靠模板匹配认出"身份证"）
2. **迈步**——点一下该点的按钮
3. **确认落地**——到没到下一个界面；没到就走恢复链回安全点

任何一步缺了第 3 件事，挂机时就会在错误的地方继续点，越走越远。

---

## 一、第一步：先手动跑通，把路线画成清单

别急着做脚本。自己手动把目标玩法完整走 **3~5 遍**，每个界面截图，边做边记：

- 经过哪些界面：登录 → 主城门 → 挂机副本入口 → 战斗 → 结算 → 领奖 → 回城
- 每个界面**凭什么认出它**：右上角固定按钮？标题文字？固定边框花纹？
- 每个界面**要点哪里**、点完**怎么知道成功了**

> 打个比方说：就像先自己走一遍迷宫拿手机拍照记路，回来后照着照片画地图——
> 很多人栽在没画地图就直接指挥机器人走，走一步瞎猜一步。

---

## 二、采素材：每个界面一张身份证 + 每个按钮一张照片

| 类型 | 采什么 | 注意 |
|------|--------|------|
| **界面身份证**（定位模板） | 界面里**永远不变**的局部：固定标题、角落 logo、边框花纹 | 避开一切会动的：血量、倒计时、伤害飘字、玩家名、抽奖内容 |
| **按钮模板** | 要点的按钮单独采 | 按钮常有"可点/灰掉"两态，**两张都采**——灰态用来判断"次数用完了" |
| **颜色点** | 红点提醒、加载进度条底色 | "只看变色不看形状"的用取色，不用找图 |
| **文字** | 剩余次数"3/5"、体力数值 | 找图搞不定的走 OCR 认字 |

阈值经验：先设 **0.9** 采高信心模板，漏判了再降；改完跑一遍「测试全部」，看真实匹配度分布，别拍脑袋。

---

## 三、流程按「节点三连」搭

每个节点一个标准姿势：

```
[检测到 界面A 的身份证?] → 点击 按钮X → [等 界面B 出现, 超时 N 秒]
        找不到 ↓（失败口）              超时没等到 ↓（失败口）
              └────── 汇到同一个「恢复」分支 ──────┘
```

- 成功 / 失败端口就是干这个的
- **每个节点都必须有失败口去向**——没有失败口的节点 = 挂机时的死胡同

### 判断节点可以挂多条条件（与/或/取反）

属性面板「＋ 添加条件」：选「满足全部（与）」或「满足任一（或）」，
每条还能单独取反（画面没有它才算成立）。多条件在**同一帧**一起判——
串联两个判断节点做不到这点（后一个要等下一拍才评），闪瞬即逝的状态
（动画里冒出来的红点、只亮一秒的角标）要判"有A且有B"就得用这里。
"或"用单条件也能连线凑（判A的N口接判B），但一条判断节点挂完更省事、
日志也只打一行。嵌套逻辑（A与B 或 C与D）不支持——拆两条判断串联即可。

### 典型子流程划分（一条活动一条链）

- **登录进城门**：起模拟器 → 等主城门身份证 → 失败重开游戏
- **单次副本循环**：判次数（OCR 读数）→ 够了跳去领奖 / 不够点挑战 → 等结算 → 点跳过确认 → 等回城
- **领奖 / 日常集合**：逐个活动页扫红点，有点进去做，没点跳过
- 各子流程做完统一回「主城门」这个**总锚点**，再进下一段

## 四、兜底比主线值钱——能不能 7×24 挂机全看这层

游戏里专出没预告的东西：弹窗（活动推广、绑定手机、版本公告）、断线重连、战斗卡顿。

### 兜底三板斧

1. **全局弹窗扫雷**：每 tick 先拿几张"弹窗关闭按钮 / 常见公告"模板扫一遍，见到就点掉再走主线
2. **超时回城锚点**：任何节点连续失败 N 次，**别原地重试**，一律强制回主城门
   （点返回连点 / 重启游戏进程），回锚点后重新计数。
   散在各处的补丁式重试，不如一个集中的「回家键」
3. **随机化**：步骤间隔别用死秒数（本项目的随机等待就是干这个的）：
   一是防风控识别出机械节奏，二是真实点击本来就不均匀

---

## 五、调试顺序：由小到大，最后故意搞破坏

1. **单节点验证**：每个模板用「测试全部」/ 预览绿框确认认得准
2. **单段跑**：只挂"进城门 → 开一次副本"这一小段，盯日志跑通
3. **全链跑**：串起一条日常，**故意制造失败**（手动点进别的界面），看它能不能自己回锚点
4. **多开压测**：按多开机的实际性能定并发数和截图间隔
5. **版本更新维护**：游戏改版先跑「测试全部」批量看哪些身份证失效，针对性补采
   —— 所以模板按界面分库、命名跟着界面走，就是为了这时候好定位

> 打个比方说：调试像装自动门——先在门口一个人一个人试感应（单节点），
> 再试整条走廊人流（全链），最后故意有人逆行撞门看它夹不夹人（负向测试）。
> 只测顺风的自动门，上线第一天就夹住。

## 六、传承玩法实战节点链

> 占位名换成你游戏里的实际名称。做之前只需**采 4 张锚点图**，流程即可落地。

```
[主城门锚点] ──找不到──> 恢复链（回城）
     │找到了
     ▼
[传承入口锚点] ──点它──> [等 传承主界面锚点, 超时5s] ──失败──> 恢复链
     │                                    │
     ▼                                    ▼
[次数判断] ◄──────────────────────────────┘
   OCR 读"剩余次数"数字，或模板匹配"次数已满"灰字
   满   ──> 跳去领奖
   未满 ──> 点[开始/传承按钮] ──> [等 战斗/进行中锚点, 超时10s] ──失败──> 重新判定次数（可能点慢了）
                  │找到了
                  ▼
      [等 结算锚点, 超时 = 单次时长 × 1.5] ──超时──> 截图查看卡哪了
                  │到位
                  ▼
      点[跳过/确认] ──> [等 回传承主界面, 超时5s] ──> 回到次数判断（循环）
```

### 循环出口只有两个

- 次数读完 → 正常结束，去领奖
- 时间窗口过（限时活动）→ 结束

**别写死循环次数在流程里**——把"剩余次数"当唯一事实来源，游戏改活动不陪你改脚本。

### 传承特有的三张必采 + 一个坑

必采：

1. **主城门锚点**：右上角固定 logo 或标题
2. **传承主界面锚点**：界面标题或固定边框标识（等于传承的"总锚点"，循环靠它归位）
3. **开始按钮**：可点态一张（必要则灰态再一张，判次数用完）
4. **结算通过的确认字样**：金色大字那类，用来终止本轮

坑：

- **入口是轮播位**：活动入口常在图集里左右滑，每天位置不同。
  定位永远认「传承主界面锚点」；入口按钮用"找到就点、找不到就左右划一下再找"的搜索子链，
  **别把流程死压在入口精确坐标上**
- **"次数已满"和"没有次数"是两个失败**：前者正常结束（去领奖/回城门），
  后者是脚本迷路了（恢复链）。失败口别都汇一处，否则分不清"活动做完"还是"脚本走丢"
- **传承奖励常见一次性弹窗**：结算后跳出的"获得XXX"弹窗，点空白区域会卡住
  —— 第一轮就把它加进全局弹窗扫雷清单

## 七、识字取物 + 流程变量：读数→判断→动作的组合配方

「识字取物」节点（旧名选区点击）一次识别可以干四种事，**用法**下拉里选：

| 用法 | 干什么 | 典型场景 |
|------|--------|----------|
| 点文字 | 认出目标文字点它中心（可选偏移+抖动） | 点列表里某个名字（进服选区选服 = 摆两个本用法节点，见配方 3） |
| 识文读数字 | 先认出带目标文字那行，再抠数字存进变量（认单位：1.17万→11700、1.2亿→120000000、1,234→1234） | 体力/金币/剩余次数，先读后判；数字旁有文字标签可当锚点时用这个 |
| 读数字 | 不找锚点，框住数字那一小块直接认，按单位换算（同上） | 资源条那种「图标+数字、没有文字可认」（图标不算锚点）；金币/钻石各摆一个节点，框里只圈一个数字 |
| 读坐标 | 把那行字的位置存进变量 | 记录/排查用（打印文本里 `{变量名}` 可显示）；认出就想点它的话直接用「点文字」用法 |

「认不出时」选**滑动翻页找**：识别窗口到期自动滑一次、等画面停稳再认，
最多滑设定次数，滑完还没有才走 N 口——轮播入口、长列表找服都用它。

变量的取用有两处：**判断/循环出口**选「变量比较」条件；任何文本框
（打印检测、识字取物的目标文字、判断节点的期望文字）里写 `{变量名}` 占位符，运行时换成现值。
变量按实例各记各的（多开互不串数），一次挂机运行内存活，流程重启归零。

同一批文本框还认 `{账号.列名}`：运行时换成**当前实例绑定账号**在账号表里那一列
（列名照表格表头写，如 `{账号.区服}` `{账号.等级}`）。判断节点期望文字写
`{账号.区服}`，多开各号各服就不用手填死值，一条流程通用；取不到（没绑账号/
列名打错）会原样留在日志里，好排查。密码列不供取。

### 配方 1：先读后判（攒够才干活）

```
[识字取物 用法=识文读数字 目标=体力 ROI=体力栏 变量=hp]
        ▼
[判断 条件=变量比较 hp>=10] ──Y──> 进本刷体力
        │N
        └──> 定时执行 / 直接收工
```

### 配方 2：滑动找列表项（轮播入口 / 长列表）

```
[识字取物 用法=点文字 目标=魂兽森林 ROI=活动栏
 认不出时=滑动翻页找：向上滑 300px × 5 次]
   认出→点它进页面    滑 5 屏还没有→N 口（多半真没开，跳去干别的）
```

### 配方 3：选区 → 选服（两个「点文字」节点串起来）

进服常是两屏：先点区，再在区里点服。摆三个节点：

```
[识字取物 用法=点文字 目标={账号.选区} 限定区域=框住区列表]
        ▼
[等待 1.5s]        ← 给"点完区、服列表加载"留余量
        ▼
[识字取物 用法=点文字 目标={账号.选服} 限定区域=框住服务器列表]
```

多开各号各服时用这两个派生列（都从账号表「区服」列现推，账号表不用加列）：
`{账号.选区}` = 区服前 4 字（含沙射影6服→含沙射影，给点区那步）；
`{账号.选服}` = 区服全名（含沙射影6服，给点服那步）。一条流程全号通用。

- **为什么第一步只认区名也可能点歪**：目标串出现在哪一行就点哪一行。
  页面标题/横幅若也带同样的字，跟列表行同为满分，先扫到谁点谁——
  **框住列表区域是硬保险**（两步都建议框）。
- **为什么第二步目标要带数字**：区里一排「含沙射影6服」「含沙射影7服」，
  数字锚点规则让缺数字的行判 0 分，6/9 不容认错；只认「含沙射影」则
  一排服全满分、点谁看运气。
- 两步各自的"认不出时"处置（退出/跳过/滑动翻页找）、偏移、抖动都在
  自己节点上配，互不牵连。
- 旧流程里如果还存着「选区选服」用法（该用法已删）：编辑器载入时自动
  换算成上面三个节点，保存后生效。

### 配方 4：循环攒数，变量当出口

循环节点的「退出条件」选变量比较，如 `hp >= 10`——
[循环体：领一次小体力] × 直到攒够，出口一眼显示「直到 hp>=10」。

### 配方 5：资源条数字入库（金币/钻石 per 账号存档）

屏幕顶上的资源条只有「图标+数字」（如金币 1.17万、钻石 695），没有文字可当
锚点 —— 用**读数字**：每个数字摆一个节点，框只圈住数字
本身（框里混进第二个数字就判"没认出"，不猜）。读进变量后接 [资产入库]，
按账号写进账本，主界面表格「资产」列/右键「查看资产」可看。

```
[识字取物 用法=读数字 ROI=只圈金币数字 变量=金币]
        ▼
[识字取物 用法=读数字 ROI=只圈钻石数字 变量=钻石]
        ▼
[资产入库 金币→"金币"、钻石→"钻石"]
```

### 排查招：把变量打进日志

怀疑"到底读没读到"时，链路上插一个 [打印检测]：
目标选「打变量值」，或文本直接写 `体力={hp} 金币={gold}`——
没读到的变量原样显示 `{hp}`，哪步没跑一眼看出。

## 八、常见坑（与本项目红线的对应）

| 坑 | 后果 | 对应防线 |
|----|------|----------|
| 分辨率三方不一致（采集基准 / 截图基准 / 安卓实际） | 识别全对、点击全偏，日志完全看不出来 | `ensure_resolution` 兜底，不许绕过 |
| 只测"顺利"路径，没测断线/顶号 | 失败口形同虚设 | 全链跑时故意制造失败 |
| 模板采太大（整屏） | 换个活动皮肤全灭 | 局部、固定、有辨识度 |
| 模板采太小 | 满屏误匹配 | 同上 |
| 用 sleep 死等 | 卡住时全链僵死 | 永远"轮询查特征 + 超时上限"（worker 不阻塞） |
| 循环次数写死在流程里 | 游戏改活动就要改脚本 | 次数读实时状态 |

---

## 九、最小起步建议

先只做这条最短链，跑稳一周再加别的：

```
登录 → 进城门 → 打一次挂机副本 → 回城
```

别一上来搭十条流程——那时兜底层还没有，坏一条全瘫。
